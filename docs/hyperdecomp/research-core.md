# Core technology feasibility

Research retrieved 2026-10-14. The machine-readable [source snapshot](../../reports/hyperdecomp/research-source-snapshot.json) records official GitHub release/license endpoints and installed CUDA file hashes. Upstream marketing and paper throughput are not application benchmarks.

| Technology | Verified status and licensing | Practical decision |
|---|---|---|
| Ghidra | Official latest release endpoint returned 12.1.4, published 2026-09-21. Native decompiler, SLEIGH processor definitions and p-code analysis are available; the main project is Apache-2.0 with separate third-party notices. Its supported CPU/format range is broader than this application's validated corpus. | Retain the already integrated pinned native backend for real CPU lifting and pseudocode. Preserve source modifications, LICENSE and NOTICE. Do not describe metadata starts or returned C text as accurate whole-program recovery. [Repository](https://github.com/NationalSecurityAgency/ghidra), [release](https://github.com/NationalSecurityAgency/ghidra/releases/tag/Ghidra_12.1.4_build) |
| LLVM | Official release endpoint and project site report 23.1.3, released 2026-10-06. SSA IR, optimizers, code generation, Object/MC and multiple CPU targets are available under Apache-2.0 with LLVM exceptions and component notices. LLVM does not itself reconstruct arbitrary machine-code programs into correct C. | Useful future parser/IR validation and selected transformations. Avoid adding a second heavy IR/decompiler dependency until lifting conventions, undefined behavior and type semantics are specified. Not newly linked here. [Project](https://llvm.org/), [license](https://github.com/llvm/llvm-project/blob/main/LICENSE.TXT) |
| Capstone | Official latest release endpoint returns 6.0.0-Alpha11, 2026-09-21; an alpha is not assumed stable. The existing application pins 5.0.6. It supplies multiarchitecture instruction decoding, not function or type recovery. BSD-style and LLVM-covered table notices both matter. | Retain the pinned paths for the existing non-x86 decoders. Upgrade only with differential decoding and corpus tests. [Project](https://www.capstone-engine.org/), [pinned license](https://github.com/capstone-engine/capstone/blob/5.0.6/LICENSE.TXT), [table license](https://github.com/capstone-engine/capstone/blob/5.0.6/LICENSE_LLVM.TXT) |
| Zydis | Official latest release endpoint returns 4.1.1, 2025-02-16, matching the application pin. MIT-licensed native x86/x86-64 decoding and encoding; this application disables its encoder. Decoding throughput alone does not imply analysis throughput. | Keep CPU x64 decoding and operand metadata. It supports bounded deterministic extraction without GPU transfer costs or a learned boundary classifier. [Repository](https://github.com/zyantific/zydis), [license](https://github.com/zyantific/zydis/blob/master/LICENSE) |
| CUDA / NVRTC | NVIDIA documents runtime CUDA C++ compilation into executable GPU code and loading through the Driver API. Windows x64 is supported. The installed optional components are pinned 12.4.127 rather than silently tracking newest SDK versions. They use NVIDIA's bundled EULA, not an assumed permissive open-source license. | Use application-owned kernels, optional runtime loading and explicit CPU fallback. Include both compiler DLLs and their license; do not package the system display driver. Measure context/JIT, transfers and kernels separately. [NVRTC documentation](https://docs.nvidia.com/cuda/nvrtc/index.html), [compatibility](https://docs.nvidia.com/deploy/cuda-compatibility/latest/index.html) |
| CUB / Thrust / CCCL | NVIDIA's consolidated header-only CCCL project includes CUB, Thrust and libcu++. CUB uses BSD-3-Clause; Thrust/libcu++ and bundled portions require the detailed Apache/LLVM/other notices in the repository license. Graph traversal is not equivalent to irregular decompiler data-flow with aliasing and widening. | Reviewed for subsequent reductions, compaction and CSR graph workloads. This milestone's small bounded top-k kernels are application-owned and do not claim a CUB/Thrust integration. [CCCL](https://github.com/NVIDIA/cccl), [license](https://github.com/NVIDIA/cccl/blob/main/LICENSE) |

See [external research](research-external.md) for DeepDi, angr, RetDec, GPU graph systems and GPU Datalog/data-flow papers, including restrictions and performance-claim scope. Neither DeepDi's reported disassembly speed nor GPU query benchmarks establish faster complete decompilation. No proprietary IDA or Binary Ninja code is used.

The initial workload decision is deliberately narrow: compare actual function-prefix fingerprints in batches. Exact integer outputs permit a strong CPU/GPU oracle, immutable corpora can remain resident, and only top-k results cross back to the host. No data-flow, graph, decoding or pseudocode pass is labeled GPU-accelerated until a working implementation and separate accuracy/performance measurements exist.
